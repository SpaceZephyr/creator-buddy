# 公众号封面提示词配方

配合 `../SKILL.md` 使用。所有配方都必须带上 Style Lock 和安全区约束。

---

## 标准骨架

```text
Use case: ads-marketing
Asset type: 2.35:1 ultra-wide horizontal cover banner for a WeChat Official Account article
Canvas: 1175 x 500 px

Primary request:
生成一张原创封面横幅，逐字使用给定文字，不增删、不改写。

CRITICAL — Center safe area:
这张图分享到社交场景时会被居中裁成 1:1 方形，只保留正中央 42.6% 的宽度
（1175px 画布上是 x 337–837）。以下内容必须完整落在这个中央方形区域内：
- {列出核心词组}
左右两翼（各约 28.7% 宽度）只放背景延伸和装饰，不放任何必须读到的信息。
不要把任何关键文字放在靠近左右边缘的位置。

Style/medium:
{粘贴 SKILL.md 里的完整 Style Lock}

Composition/framing:
{选中的版式，来自 references/cover-layouts.md}
主标题占画布高度 {28%–42%}
左右外边距 5%–7%，上下外边距 10%–14%
装饰簇最多 2 组，全部放在两翼

Color palette:
背景 #FCFBFF；文字 #181A24；强调 {科技紫 #6C35E8 / 青柠绿 #A4E927 / 电光蓝 #4563F2}
约 72% 白底、18% 黑字线条、10% 彩色强调

Text (verbatim):
- 主标题第一行："{文字}"
- 主标题第二行："{文字}"
- 标签（可选）："{文字}"
- 强调词（用渐变或青柠绿）："{词}"

Constraints:
2.35:1；文字逐字准确；简体中文现代无衬线粗体；层级清晰；
缩小到消息列表尺寸仍可读；关键文字远离左右边缘

Avoid:
{粘贴固定负向约束}
```

## 无输入图片（从零生成）

不传 `referenced_image_paths`，不传 `num_last_images_to_include`。

在 `Scene/backdrop` 里补一句：

```text
Scene/backdrop: 纯净的白到极浅薰衣草渐层，无实物场景，无摄影质感，
两翼可有极低对比度的线性装饰（浏览器线框、流程节点、点阵、细短线），透明度不超过 10%。
```

---

## 有主体图（产品 / 人物）

本地图片必须先用 `view_image` 检查再传。

- 全部有本地路径 → 用 `referenced_image_paths`
- 只存在于当前对话 → 用覆盖全部目标图的最小 `num_last_images_to_include`
- **两者不能同时用**

```text
Input images:
- 图 1：主体图。必须保留其身份特征、外形、包装、标识位置和关键结构。
Subject placement:
主体居中放置，完全落在中央安全区内。
主标题不得压住脸部、双手、产品名或关键卖点。
背景服务于主体，不制造第二个视觉中心。
```

> 主体和标题都要挤进 500px 宽的安全区会很紧。此时把标题压到 **8 字以内**，或改用「中央主体 + 标题叠压」版式。

## 有风格参考图

```text
Input images:
- 图 1：仅作视觉语言参考。只借鉴其配色关系、信息层级、卡片结构、线条粗细和留白节奏。
  不得复制其账号名、Logo、水印、标题文案、段落、插画或逐像素版式。
  构图必须原创。
```

## 三张变体

逐张调用 `image_gen`，每张写明差异。**不要只换颜色**。

```text
变体 1：中央大字。标题两行居中，两翼纯留白 + 极淡点阵。强调色用科技紫渐变。
变体 2：中央标题卡。白色大圆角卡片承载标题，背景浅薰衣草柔光延伸至两翼。强调色用青柠绿。
变体 3：中字翼饰。标题居中，两翼各一组线性图标（左：文档/流程；右：目标/盾牌），紫色细描边。
```

## 定向修正模板

一次只修一个问题。

### 修文字错误

```text
仅修正主标题第二行，把"{错误文字}"准确改为"{正确文字}"。
其他文字、构图、颜色、装饰和主体全部保持不变。
```

### 修安全区越界

```text
仅把主标题整体向{左/右}移动约 {N}%，使"{核心词组}"完全落入画面正中央的方形区域
（1175px 宽画布上的 x 337–837 范围）内。
不要改变字号、颜色、构图、装饰和背景。
```

### 修标题太挤

```text
仅把主标题字号缩小约 12%，并把行距增加约 15%，使两行之间有清楚的呼吸空间。
标题仍需完整落在中央方形安全区内。其他元素全部不变。
```

### 修装饰抢戏

```text
仅降低左右两翼装饰元素的对比度和透明度，使其明显退到背景层，
不与主标题争抢视线。装饰的位置和形状保持不变，其他元素全部不变。
```

### 修小尺寸不可读

```text
仅增大主标题字号约 20%，并加粗字重。
标题仍需完整落在中央方形安全区内，且与上下边缘保持至少 10% 的边距。
其他元素全部不变。
```

## 无字底图回退

同一段文字连续两次仍生成不正确时，改走这条：

```text
生成同样风格的封面底图，但**不要包含任何文字**。
在画面正中央预留一块空白区域（约占画布宽度的 42%、高度的 45%），
该区域内保持干净的浅色背景，不放装饰，用于后续叠加可编辑文字。
两翼保留装饰和背景延伸。
```

拿到底图后告知用户：文字将以可编辑方式叠加，并转 `space-wechat-layout` 或外部工具完成文字层。

## 生成后必跑

```bash
python3 ../scripts/check_cover.py 路径/cover-01.png --safe-zone --share-preview --thumbnail
```

三张产出各看一眼：

| 文件 | 看什么 |
|---|---|
| `-safezone.jpg` | 压暗区里有没有关键文字？红框内是不是核心词组？ |
| `-share-1x1.jpg` | **分享出去还读得通吗？**读不通就是不合格 |
| `-thumb.jpg` | 消息列表尺寸下，2 秒内能读懂吗？ |
