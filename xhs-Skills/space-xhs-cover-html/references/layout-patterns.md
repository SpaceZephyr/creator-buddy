# 版式图谱：两种内容形态 × 六个变体

本 skill 只做两种封面内容形态。**先定形态，再定风格**——形态由内容决定，风格由气质决定，两者独立。

```
内容有 3–5 个可并列的点  → 形态 A：大字 + 短目录   data-layout="toc"
内容是一个判断/一个承诺   → 形态 B：大字 + 副标题   data-layout="sub"
```

判断口诀：**能拆成条的拆成条（A），拆不动的就把话说狠（B）。**

---

## 形态 A：大字 + 短目录 `data-layout="toc"`

像一本书翻开的目录页。小红书上收藏率最高的一类封面——用户点进来是为了"把这几条存下来"。

**结构**：角标 → 主标题（2–3 行）→ 3–5 条目录 → 账号名
**字数**：主标题 ≤14 字 + 每条 ≤12 字，总计 ≤ 60 字
**适用**：合集、方法论拆解、工具清单、避坑条目、流程步骤、多点测评

### 目录变体（`data-toc`）

| 变体 | 视觉 | 风格适配 | 注意 |
|---|---|---|---|
| `num` | `01 02 03` 前导零编号，accent 色 | Linear / Vercel / Stripe / IBM —— 系统感强的品牌 | 编号列固定宽度，条目左边缘必须对齐 |
| `line` | 每条下一根细分隔线 | Apple / Notion / Claude —— 克制的编辑感 | 最后一条不要线；线用 `--hairline`，别用实黑 |
| `dot` | 小圆点项目符号 | Airbnb / Figma / Miro —— 轻快友好 | 圆点 16–20px，太小在缩略图里消失 |
| `card` | 每条一个浅色卡片 | Notion / Supabase / Raycast —— 组件化气质 | 5 条卡片会撑满，条数 ≥4 时改 `line` |

### 条数与字号

| 条数 | `--t3` | 条间 gap |
|---|---|---|
| 3 条 | 60px | 28px |
| 4 条 | 56px | 24px |
| 5 条 | 50px | 20px |
| ≥6 条 | 不做——超过 5 条封面就读不清了，多的挪到内页 |

**目录条目的写法**：每条是 `名词 + 冒号 + 一句结论`（"复盘：只看两个指标"），不要写成完整句子，也不要只写一个孤零零的名词。条目之间**句式要平行**——四条都是"动词+名词"或四条都是"名词：结论"，混着写在缩略图里像乱码。

**红线**：封面写 5 条，正文就必须有这 5 条，且顺序一致。

## 形态 B：大字 + 副标题介绍 `data-layout="sub"`

一句话把人拍住，再用一行小字兑现。适合没有可并列结构的内容。

**结构**：角标 →（可选标签）→ 主标题（1–3 行）→（可选 `.rule` 细线）→ 副标题 1–2 行 → 账号名
**字数**：主标题 ≤14 字 + 副标题 ≤24 字，总计 ≤ 38 字
**适用**：观点输出、个人故事、经验复盘、单品种草、教程结果预告、认知颠覆

### 对齐变体（`data-align`）

| 变体 | 视觉 | 风格适配 |
|---|---|---|
| `left` | 左对齐、垂直居中偏上 | Linear / Vercel / Supabase / IBM —— 工程理性 |
| `center` | 全居中 + 居中细线 | Apple / Tesla / Nike / SpaceX —— 宣言式、留白大 |

### 主标题与副标题的分工

- **主标题给情绪或反差**，副标题给**具体兑现物**。
  - 主：`这五件事我全交给 AI` → 副：`从选题到成图的完整配置清单，照着抄就行`
  - 主：`2000 块改造出租屋` → 副：`清单 + 链接 + 避坑，全在正文`
- 副标题**不许复述主标题**。复述 = 白占一层信息层级。
- 副标题里放"数量词/时长/价格/门槛"最有效：`零基础 · 全程免费 · 附模板`。

**`.rule` 细线什么时候用**：主标题和副标题的字号差 < 2 倍时用它做视觉断层；差得够大（如 132px vs 56px）就不用，留白已经够了。

**红线**：主标题承诺的东西，正文必须兑现。

## 两种形态怎么选（拿不准时）

| 情况 | 选 |
|---|---|
| 用户给的是清单/合集/N 个 X | A |
| 用户给的是一段观点或一个故事 | B |
| 内容能拆条但只有 2 条 | B（2 条不成目录，合并成一句） |
| 内容有 7 条以上 | A，但封面只放最强的 4 条 + 主标题写"7 个"，其余进内页 |
| 教程类 | A（目录写成 Step）或 B（副标题写门槛），取决于步骤是否 ≥3 |
| A/B 都成立 | **两版都做**，让用户挑——渲染成本几乎为零 |

## 组图分工（首图 vs 内页图）

本 skill 的规则是给**首图**定的。内页图是另一套标准，别混用。

| | 首图（第 1 张） | 第 2 张 | 中间页 | 末页 |
|---|---|---|---|---|
| 唯一 KPI | **点击率** | **留人率** | 价值兑现 | 收藏 / 关注 |
| 信息密度 | 最低 | 中：给总览 | 高：可上表格、长文、截图 | 低 |
| 字号 | 主标题 ≥90px | ≥64px | 40–56px 都可以 | ≥64px |
| 设计投入 | 70% | 20% | 10% | — |

**关键认知**：首图按**缩略图**（260px）标准做，内页按**全屏详情页**标准做。所以内页允许更小的字和更密的信息——不要用首图的字号红线去限制内页，那会让内页信息量白白浪费。

### 页序模板

| 笔记类型 | 张数 | 页序 |
|---|---|---|
| 干货清单 | 6–9 | 首图（形态 A）→ 总览 → 每条一页 → 收藏引导 |
| 教程 | 5–8 | 首图（形态 B，写结果）→ 前置条件 → Step 1..N → 成品 + 避坑 |
| 方法论拆解 | 5–7 | 首图（形态 A）→ 背景 → 每步一页 → 复盘 |
| 个人故事 | 4–6 | 首图（形态 B）→ 时间线 → 转折 → 结果 → 感悟 |

### 组图一致性

- **全组同比例**（3:4 到底），显示以第一张为准，混比例会导致划动跳动、内页被裁。
- **全组同一套 `:root` token**：内页 HTML 复制首图的 token 块，只改布局和字号。
- 第 2 张**不许重复首图的话**，要接住悬念并立刻给一点干货。
- 批量出图：把每页写成 `pages/01.html … 08.html`，一条命令渲染全组：
  ```bash
  python3 scripts/render_cover.py --html-dir pages/ --out-dir out/ --ratio 3:4
  ```
