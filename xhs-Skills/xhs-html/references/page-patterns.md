# 多页图文结构与页面组件

先选内容结构，再选视觉组件。不要让版式反过来决定内容。

## 目录

1. 页数档位
2. 四类内容页序
3. 页面组件
4. 实操性检查

## 一、页数档位

### 6 张：精简版

1. 封面
2. 核心结论 / 总览
3. 第一步
4. 第二步
5. 示例 / 模板
6. 验收 / 总结

适合：结论少、步骤短、单一工具或单一方法。

### 7 张：标准版

1. 封面
2. 为什么值得看 / 最终结果
3. 准备
4. 步骤 1
5. 步骤 2
6. 示例 / 常见错误
7. 验收 / 复用

适合：一个完整方法、清单或轻量教程。

### 8 张：实操版

1. 封面
2. 结果预览
3. 输入 / 准备
4. 规则 / 口径
5. 可复制执行材料
6. 小样试跑
7. 输出结果
8. 验收与复用

适合：SOP、AI 工作流、表格处理、软件教程。默认优先推荐。

### 9 张：深入版

在 8 张结构上增加一张：

- 对照示例
- 失败案例与修正
- 第二个关键步骤
- 进阶配置

适合：原文信息充足、需要完整教学的内容。

用户可要求 10 张以上，但每增加一页都必须有独立价值，不能用空话凑页数。

## 二、四类内容页序

### 教程 / SOP

封面结果 → 成品预览 → 准备 → 规则 → Step 1 → Step 2 → 输出 → 验收

每一步都回答：

1. 做什么
2. 具体怎么做
3. 做完看到什么

### 干货清单

封面利益点 → 全部条目总览 → 每 1–2 条一页 → 示例 → 收藏清单

清单条目必须句式平行。不要一页全是名词，下一页突然写长段故事。

### 方法论

封面判断 → 旧做法的问题 → 新框架 → 框架各环节 → 案例 → 适用边界 → 复盘

方法论必须至少落到一个具体例子，不能只画抽象流程图。

### 个人经验 / 故事

封面反差 → 起点 → 问题 → 关键转折 → 做法 → 结果 → 可复制经验 → 结尾

结尾提炼可复制经验，不写“所以大家一定要努力”之类说教句。

## 三、页面组件

同一组内至少使用 3 种组件，避免每页都是四宫格。

| 组件 | 适合内容 | 使用限制 |
|---|---|---|
| 大标题 + 一句话 | 封面、转场、结论 | 信息少，留白大 |
| 两栏对照 | Before/After、错误/正确 | 两边句式对称 |
| 三步流程 | 操作链路 | 每步不超过 3 行 |
| 表格 | 字段、样例、验收数据 | 建议 ≤6 行、≤6 列 |
| 文件夹树 | 自动化、资料整理 | 使用等宽字体 |
| 代码 / 提示词卡 | 可复制材料 | 保留完整语义，不做假代码 |
| 清单 | 验收、准备、避坑 | 每页 4–6 条 |
| 单一大数字 | 结果、阈值、时间 | 一页只突出一个数字 |
| 输出文件卡 | 文件名、字段、产物 | 2–4 张并列 |
| 时间线 | 故事、流程、计划 | 节点 3–5 个 |

### 页面节奏

- 第 1 页：留白最大。
- 第 2 页：立即给结论或成品，不写背景长文。
- 中间页：信息密度最高，但一页仍只有一个主问题。
- 倒数第 2 页：给输出、案例或易错点。
- 最后一页：给验收、复用或完整清单。

## 四、实操性检查

交付前问：

- 用户能否照着某一页直接操作？
- 是否有可复制的文字、字段、命令或模板？
- 是否说明了输入是什么、输出是什么？
- 是否给出至少一个具体例子？
- 是否告诉用户怎么判断结果正确？

如果五个问题中有两个以上回答“否”，先补内容，不要继续美化排版。
